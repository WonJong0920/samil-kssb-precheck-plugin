# 근거 매핑 규칙 (Evidence Mapping Rules)

이 문서는 각 판정에 붙는 **근거 앵커(evidence anchor)**의 형식과 인정 규칙을 정의한다.
목적은 모든 판정이 원문에 추적 가능하도록 하여 컨설턴트 검수를 가능하게 하는 것이다.

## 1. 근거 앵커 필드

| 필드 | 필수 | 설명 |
|---|---|---|
| source_id | 권장 | 원본 문서 식별자(보고서명 등) |
| quote | 필수(또는 위치단서) | 원문 인용문(발췌). 자료에 실제로 존재하는 문장만 사용 |
| 위치 단서 | 필수(또는 quote) | 섹션/제목 경로, 표 식별자, (제공 시) 페이지 등 |
| heading_path | 권장 | 근거가 속한 제목 경로 |
| table_id | 표인 경우 | 표 식별자 |

- **"근거 확인" 및 "일부 근거 확인" 판정에는 근거 앵커가 최소 1개 이상 필수**다. 근거 없이 "확인" 판정을 부여하지 않는다.
- "확인 불가" 판정에는 근거 앵커가 없다(대신 고객 확인 질문으로 연결).

## 2. 근거 인정 규칙

- **직접 근거만 인정한다.** 추론·업계 상식·외부 지식은 근거가 아니다.
- 표현·동의어 차이로 근거를 놓칠 수 있다. **매칭 실패는 미공시 확정이 아니다** → "확인 불가"로 표시하고 질문으로 연결.
- 근거로 쓰는 인용문은 자료에 존재하는 원문이어야 한다. **출처 없는 숫자·문장을 생성하지 않는다.**

## 3. 정량 근거 특칙

- 정량요구 항목(예: 온실가스 배출량, 에너지 사용량)은 **수치가 결합된 근거**만 정량 근거로 인정한다.
- 수치 없이 정성 서술만 있으면 "일부 근거 확인, 보완 필요"로 낮춘다.
- **에너지 사용량(metric-04)**: 에너지 의미 표현 + 수치 + 에너지 단위(kWh/MWh/TJ/GJ/toe 등)가 결합될 때만 정량 근거로 인정한다.
  온실가스 배출량 수치(tCO2eq/Scope)는 에너지 사용량의 직접 근거가 아니다.
- 정밀 매칭 특칙: 특정 지표는 앵커 표현으로 과매칭을 막는다(예: Scope 1·2 항목에 "Scope 3" 문장을 근거로 섞지 않는다).

## 4. 상충 근거 처리

- 같은 항목에서 서로 모순되는 서술(예: "미산정" ↔ 수치 존재)이 확인되면 **"상충 또는 해석 필요"**로 판정하고 사람 검수로 넘긴다.
- 상충은 자동으로 해소하지 않는다. 기준·범위·기준연도를 고객 확인 질문으로 정리한다.

## 5. 신뢰도 표현 주의

- 판정에 붙일 수 있는 신뢰도/강도 표현은 **키워드·근거 강도 기반 휴리스틱**일 뿐 통계적 신뢰도가 아니다.
- 신뢰도 표현은 사람 검수를 대체하지 않는다. 확정·보증 표현으로 쓰지 않는다.

## 6. 스캔/이미지/저신뢰 구간 라우팅 (L1, 선택적 인테이크 신호)

선택적(core 밖) 인테이크 어댑터(`src/intake/dei_producer.py`)가 이미 로컬에서 추출된 인테이크 산출물을
**DEI-candidate**(문서 수준 근거 재료)로 정규화해 제공할 수 있다. Skill은 그 신호를 **근거 재료로만** 읽고,
아래 규칙으로 **기존 판정 경로**에 연결한다(스키마 변경 없음).

- **판독 불가/저신뢰 신호**(`needs_ocr` / `extraction_quality: low` / `warnings`에 `SKIPPED_IMAGE` / `review_priority_hints`)가
  붙은 구간은 **미공시로 단정하지 않는다**(§2 재확인). →
  - `judgment_code = not_verifiable`(모드별 라벨 "제공자료로 확인 불가" / "공개자료로 확인 불가"),
  - `missing_info` ≥ 1: 판독 불가 구간과 **그 위치 단서**를 명시(예: `"p.12 스캔 페이지(텍스트 레이어 없음): 자동 판독 불가"`),
  - `customer_questions` ≥ 1: 기계판독 가능한 원문/데이터를 요청하며, **위치 단서는 질문의 `requested_material`/사유에 함께** 적는다. 우선순위는 `review_priority_hints.priority`를 **참고**하되
    Skill이 근거를 보고 판단한다(priority를 판정으로 직접 매핑하지 않는다).
  - **evidence anchor를 만들지 않는다**: `not_verifiable`(§1·§2)에는 근거 앵커가 없다. 판독 불가 구간의 위치는 위 `missing_info`/고객질문 쪽에 싣고, **`evidence_anchor.page_or_section`에는 넣지 않는다**(없는 quote로 앵커를 만들지 않는다).
- **위치 표기 규칙(구분)**:
  - **읽을 수 있는 근거(confirmed / partial 판정)**에만 `evidence_anchor`를 만들고, 그 `page_or_section`에 사람 읽기용 `p.<n> · <섹션>` 최소 표기를 넣는다(원문 `quote` 필수).
  - **판독 불가(not_verifiable)**의 위치 단서는 `evidence_anchor`가 아니라 `missing_info`/고객질문에 싣는다.
  - **bbox 좌표는 어느 경우에도 findings에 넣지 않는다**(DEI 문서수준 재료에만 — 숨은 구조 스키마화 방지).
- **금지(재확인)**: 판독 불가 구간에서 **차트 수치 읽기·이미지 의미 해석·KSSB 충족 추정 금지.**
  DEI의 `extraction_quality`/`needs_ocr`/priority는 **검수 트리아지 신호**이지 판정이 아니다. 최종 판단은 컨설턴트 검수.
- **(L2 ingest, 2L-4B) OCR 유래 텍스트(`ocr_supplement`) 취급**: DEI에 `ocr_supplement` 섹션이 있으면 그 텍스트는
  **승인 기반 로컬 assisted OCR runner(2N-4L 최소 page-set 경로) 또는 out-of-band 도구의 산출물**
  (extraction_quality=low 고정, provenance 포함)이다. 이를 인용으로 쓸 경우
  ① 인용 출처에 **OCR 유래임을 표기**하고(예: `"…" (OCR 추출)`), ② **OCR 인용 단독으로 confirmed로 승격하지 않는다**
  — 보수적으로 partial/not_verifiable 쪽으로 매핑하고 원문 확인을 `customer_questions`로 요청한다(컨설턴트 검수 필수).
- **(L2 ingest, 2L-4B) 보조 구조 gap 신호(`aux_structure`·hint)**: `image_detection_gap`·`table_count_mismatch`·
  `review_required_reason` 등은 **검수 신호일 뿐**이다 — 판정·anchor로 변환하지 않고, 필요 시 `missing_info`/
  `customer_questions`(누락 가능 구간의 자료 요청)로만 라우팅한다.
- **범위 경계**: **core는 OCR을 자동 실행하지 않는다** — 문자 인식은 core 밖 **승인 기반 로컬 assisted runner의
  최소 page-set 경로**(2N-4L: 문서의 판독 필요 페이지만·자동 실행 없음·산출물은 이 §6 규칙으로만 합류)로 제공되며
  "OCR 지원 완료"가 아니다. 도표/차트 구조 분류(L3)는 planned/미구현.
  L2는 partially implemented — **repo-side ingest boundary는 implemented+reviewed(2L-5 closure)**, provider 최종 확정·Skill 자동 통합은 pending.
  L1은 "판독 필요 구간을 감지·위치·질문으로 라우팅"까지다.

## 7. 사용자-facing 문구·인용 품질 규칙 (2M-5 — 산출물 품질 검수 반영)

findings의 사용자-facing 필드(인용·missing_info·질문·사유·권고·overall_limitations)에 적용한다.
샘플 산출물 검수(2M-3A/3B)에서 관찰된 재발 방지 규칙이며, 렌더러는 findings를 그대로 변환하므로 **작성 시점에** 지켜야 한다.

- **문서 커버리지 명시(필수)**: 입력 문서에 텍스트 미추출 페이지(스캔/이미지·zero-text)나 판독 미지원 구간이 있으면,
  `overall_limitations`에 **문서별 실제 수치로** 명시한다 — 예: `"총 359페이지 중 35페이지는 텍스트가 추출되지 않아 이번 검토 범위에서 제외됨"`.
  전량 판독 불가(스캔 전용)·형식 미지원(예: HWP v5)도 같은 방식으로 명시한다. 검토되지 않은 범위가 있는데 이를 밝히지 않으면
  "일부 근거 확인"이 문서 전체 검토처럼 오독된다(커버리지 침묵 금지).
- **검토 범위 명시(필수)**: 카탈로그 전체 대비 실제 검토한 항목 수를 `overall_limitations`(또는 검토 개요 서술)에 1줄로 밝힌다 —
  예: `"이번 검토는 요구사항 카탈로그 중 4개 항목(영역당 1개)을 대상으로 함"`.
- **사용자 문구는 한국어·비기술 표현**: missing_info·질문사유·한계 문구에 **내부 도구/제공자 이름(예: 특정 OCR 엔진·파서명)·영문 상태 문자열을 넣지 않는다.**
  표준 문구 예시 — 스캔 전용: `"스캔/이미지 기반 PDF로 텍스트 레이어가 없어 자동 판독 불가(전체 N페이지). 기계판독 가능한 원문 필요"` /
  zero-text 혼재: `"p.X 등 M개 페이지는 텍스트가 추출되지 않아 자동 검토 제외"` / 형식 미지원: `"해당 파일 형식은 현재 자동 판독을 지원하지 않아 기계판독 가능한 사본 필요"`.
- **인용 품질**: 인용(quote)은 **문장 경계 단위**의 의미 있는 원문이어야 한다. 목차 점선줄·표 머리글 뭉침·번호 달린 제목 조각 **단독** 사용 금지
  (제목만 있고 본문 근거가 없으면 그 항목은 확인 불가로 처리). **서로 다른 항목에 동일 인용을 재사용하지 않는다** — 항목별 적합 인용이 없으면
  해당 항목은 `not_verifiable`로 두고 질문으로 라우팅한다(validator가 `evidence.duplicate_quote_reuse` warning으로 감지).
- **사유-상황 일치**: 질문사유는 실제 상황과 일치해야 한다 — 근거가 일부 확인된 항목(partial)은 "확인된 근거만으로는 충분성을 확정할 수 없어",
  판독 불가 항목(not_verifiable)은 "문서가 자동 판독되지 않아(스캔/미지원 등) 근거를 확인할 수 없어"로 구분해 쓴다(보일러플레이트 교차 사용 금지).
- **내부/테스트 어휘 금지**: 사이클명(예: "Cycle 2M-3")·Track·"샘플 자동 산출 테스트"류 **작업 하네스 어휘를 사용자-facing 텍스트에 넣지 않는다**
  (그런 맥락 설명이 필요하면 내부 로그·evidence 문서에만).
