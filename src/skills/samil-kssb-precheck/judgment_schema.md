# 판정 스키마 (Judgment Schema)

Samil KSSB Precheck는 각 KSSB 공시요구 항목에 **하나의 판정 라벨**을 부여한다.
판정 라벨은 입력 모드에 따라 두 세트 중 하나를 사용한다. "근거 확인"의 근거 표기(제공자료/공개자료)만
달라지고 판정 논리는 동일하다.

## 실제 고객자료 모드

| 판정 라벨 | 의미 | 후속 처리 |
|---|---|---|
| 제공자료상 근거 확인 | 제공자료에서 해당 공시요구를 뒷받침하는 근거가 확인됨(준수 확정 아님) | 근거 인용 첨부 |
| 일부 근거 확인, 보완 필요 | 근거 일부만 확인(예: 정량 요구인데 수치 없음) | 보완 질문·요청자료 권장 |
| 제공자료로 확인 불가 | 제공자료만으로 확인 불가 | **반드시 고객 확인 질문으로 연결** |
| 상충 또는 해석 필요 | 자료 내/자료 간 상충하거나 해석이 필요한 근거 존재 | 사람 검수(수동 검토) 필요 |
| 검토 범위 외 또는 적용대상 아님 | 조건부 항목이며 적용 조건이 자료에서 확인되지 않음 | 정보 제공, 갭 아님 |

## 해커톤 공개자료 검증 모드

| 판정 라벨 | 의미 | 후속 처리 |
|---|---|---|
| 공개자료상 근거 확인 | 공개자료에서 해당 공시요구를 뒷받침하는 근거가 확인됨(준수 확정 아님) | 근거 인용 첨부 |
| 일부 근거 확인, 보완 필요 | 근거 일부만 확인 | 보완 질문·요청자료 권장 |
| 공개자료로 확인 불가 | 공개자료만으로 확인 불가 | **반드시 고객 확인 질문으로 연결** |
| 상충 또는 해석 필요 | 상충/해석 필요한 근거 존재 | 사람 검수 필요 |
| 검토 범위 외 또는 적용대상 아님 | 조건부 항목이며 적용 조건 미확인 | 정보 제공, 갭 아님 |

## 판정 결정 순서 (권장)

각 항목에 대해 입력 자료에서 근거를 탐색한 뒤 다음 순서로 판정한다.

1. 조건부 항목이고 적용 조건 근거가 없음 → **검토 범위 외 또는 적용대상 아님**
2. 근거가 있으나 상충/해석이 필요함 → **상충 또는 해석 필요**
3. 정량요구 항목이고 근거 + 유효 수치(요구 단위 포함)가 있음 → **(제공/공개)자료상 근거 확인**
4. 정량요구 항목이고 근거는 있으나 유효 수치가 없음 → **일부 근거 확인, 보완 필요**
5. 비정량 항목이고 근거가 있음 → **(제공/공개)자료상 근거 확인**
6. 근거가 없음 → **(제공/공개)자료로 확인 불가** → 고객 확인 질문 생성

## 금지

- "준수", "적합", "인증", "감사 의견", "적정" 처럼 보이는 판정명을 **절대 사용하지 않는다.**
- "근거 확인"은 근거가 존재한다는 뜻일 뿐, **KSSB 준수 확정·감사·인증이 아니다.**
- 확인 불가 항목을 "미공시"로 단정하지 않는다. 질문으로 전환한다.

## 참고: 내부 표기와의 관계

참고 엔진(기존 1차 작업물)은 내부적으로 `SUPPORTED / PARTIAL / NOT_VERIFIABLE / CONFLICT / OUT_OF_SCOPE`
enum을 사용했다. 본 스킬의 사용자-facing 라벨은 위 한국어 라벨을 표준으로 하며, 내부 enum은 노출하지 않는다.
매핑: SUPPORTED→근거 확인 / PARTIAL→일부 근거 확인, 보완 필요 / NOT_VERIFIABLE→확인 불가 /
CONFLICT→상충 또는 해석 필요 / OUT_OF_SCOPE→검토 범위 외 또는 적용대상 아님.
