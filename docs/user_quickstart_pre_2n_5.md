# 사용자 Quickstart — 지원 문서 유형 · 승인 흐름 · 산출물 기대치 (Pre-2N-5)

> **성격**: 처음 사용하는 사용자/심사자를 위한 **요약 안내**입니다(P2N5-UX-MAJ-01 대응).
> 상세 근거·정책은 각 링크 문서가 기준이며, 이 문서는 현재 구현 상태를 **과장 없이** 한 장으로 모읍니다.

## 1. 이 플러그인은 무엇인가 (한 문장)

**공개 보고서(또는 고객 제공자료)를 근거로 KSSB 공시 요구사항별 확인 근거·보완 필요사항·고객 확인 질문을
정리한 "컨설턴트 검수용 사전검토 보고서 초안"을 생성하는 도구**입니다.

## 2. 사람 검수 경계 (반드시 읽어 주세요)

이 도구는 **감사의견·인증의견·준수 확정·법적 판단을 자동으로 내리지 않습니다.** 산출물은 초안이며
**최종 판단은 사람(컨설턴트)이 합니다.** "근거 확인"은 자료에 근거 문장이 존재한다는 뜻일 뿐,
KSSB 준수 확정이 아닙니다. 확인 불가 항목은 미공시로 단정하지 않고 "고객 확인 질문"으로 연결됩니다.

## 3. 파일 유형별 지원 현황 (handling matrix)

| 파일 유형 | 현재 기대 동작 | 승인/assisted 필요 | fallback / 제한 | 2N-5에서 확인할 것 |
|---|---|---|---|---|
| **텍스트 레이어 PDF** | **기본 경로** — 텍스트 근거 분석 → findings → 보고서 초안. **(권장·선택) 구조 보강 판독**: 승인 시 표·섹션·페이지 위치·도표 주변 맥락을 함께 판독해 근거 표시 품질을 높임 | 기본 경로 불필요 / **구조 보강 판독은 승인 기반 선택**(도구 설치·실행 각각) | 도구 부재·거부·실패 시 **구조 보강 없이 기본 경로로 계속**(검토 자체는 중단되지 않음) | 보고서 생성·구조 보강 승인/거부 UX·근거 표시 품질 |
| **혼합 PDF**(일부 페이지 텍스트 없음) | 기본 경로 보고서 + **판독 불가 페이지는 실수치로 한계 공시**. **(선택) 문자 인식(OCR) 보조 판독**: 승인 시 **'판독 필요' 신호가 있는 페이지만** 문자 인식해 검수용 보조 재료로 추가 | OCR은 **별도 승인 필요**(도구 설치·실행 각각 — 자동 실행 없음) | 거부/부재/실패/제한시간 초과/무결성 불일치 → 기본 경로 + "확인 불가 → 질문" 라우팅(허위 근거 금지) | 한계 공시 정직성·'판독 필요' 페이지만 OCR되는지·OCR 텍스트가 보조 재료로만 쓰이는지 |
| **스캔/이미지 전용 PDF** | 기본 경로만으로는 **실질 근거 분석 불가**(정직 안내 + 전 항목 확인 불가/질문). **(선택) 문자 인식(OCR)**: 승인 시 전 페이지를 상한·제한시간 안에서 문자 인식 — 결과는 **정확도 미보증 검수용 보조 재료** | **필요**(OCR 도구 설치·실행 각각 승인 — 언어 인식 데이터의 별도 출처가 함께 고지됨) | 거부/부재/실패 시 정중 안내 + 전 항목 확인 불가/질문 처리. **승인 없이 OCR이 실행되는 일은 없음** | 승인/거부 UX·백지 렌더 방어·허위 근거 앵커 0·검수 경계 문구 |
| **DOCX** | 선택적 **보조 판독 경로**(승인 기반) → 구조·텍스트 추출 → 문서 수준 근거 재료 | **필요**(도구 설치·실행 각각 승인) | 거부/실패 시 기본 텍스트 검토로 계속(한계 문구 표시) | 문서 수준 위치 표기(허위 페이지 좌표 없음)·산출 연계 |
| **HWPX** | DOCX와 동일(보조 판독 경로) | **필요** | 동일. 보조 구조 신호(표/이미지 교차확인)는 일부 경로에서만 생성 | 동일 + 한계 표시 |
| **HWP(v5)** | **보조 판독 경로가 사실상 필수**(HWP는 이 경로만 구조 판독 가능) | **필요** | 미설정/거부 시: 판독 불가를 정직히 안내하고 확인 불가/질문으로 수렴(오류 흔적 노출 없음) | 승인 흐름 전체·미설정 시 안내 품질 |
| **미지원/손상 파일** | 정중한 범위 밖 안내 또는 fail-fast(조용한 오처리 금지) | — | 허위 근거를 만들지 않음 | traceback·내부 경로 노출 없이 안내되는지 |

## 4. 현재 상태 구분 (무엇이 완성이고 무엇이 아닌가)

| 구분 | 내용 |
|---|---|
| **core (구현+리뷰 완료)** | Skill(판단 절차) → 구조화 findings → 검증기(detect-only) → 렌더러/전달(재판정 없음) → 사람 검수 |
| **baseline 사용 가능** | 텍스트로 읽을 수 있는 자료의 근거 분석·보고서 초안 생성 |
| **선택적 assisted (승인 기반)** | HWP/HWPX/DOCX 구조 판독, **PDF 구조 보강 판독(텍스트 PDF 포함 — 권장·선택)**, **스캔/혼합 PDF의 최소 문자 인식(OCR) 경로**(문서의 '판독 필요' 페이지만·페이지 상한/제한시간 내), Windows Node 부재 시 portable Node fallback(채택 — D90). 전부 승인 후 repo 밖 설치·네트워크 차단(no-egress) 훅 아래 실행 |
| **pending / provisional** | 판독 도구 최종 확정, 보조 경로의 Skill 자동 통합, OCR 실행 한도 기본값의 실 스캔 실측 보정, L2 나머지 |
| **미지원(현재)** | **무승인 자동 OCR**(어떤 경우에도 승인 없이 실행되지 않음), 이미지·차트·표의 **의미 해석**(L3) |

과장 주의: **core 플러그인은 OCR을 자동 실행하지 않습니다.** OCR은 승인 기반 로컬 보조 경로의 **최소 구현**이며
"OCR 지원 완료"가 아닙니다 — 결과 텍스트는 정확도가 보증되지 않는 검수용 보조 재료로만 쓰입니다.
위 표 밖의 문서(계획/evidence 문서)에 나오는 OCR·HWP 관련 내용은 **검증 기록이지 완성 선언이 아닙니다.**

## 5. 도구 준비 승인 흐름 (왜 물어보는지, 거부하면 어떻게 되는지)

HWP/HWPX/DOCX 구조 판독에는 로컬 판독 도구(Node 기반)가 필요할 수 있습니다. 플러그인은 **아무것도 몰래
설치하지 않습니다** — 항상 한국어 안내 후 명시적 동의를 받습니다.

- **왜 필요한가**: HWP 계열 문서의 구조·텍스트를 읽으려면 별도 판독 도구가 필요합니다(특히 HWP v5).
- **어디에 설치되나**: 이 저장소 **밖**의 사용자 홈 전용 폴더(tool-cache)에만. **제거는 폴더 삭제로 끝**납니다.
  OS 설치 프로그램 실행·시스템 PATH 영구 변경·관리자 권한이 **없습니다.**
- **Node가 없는 컴퓨터라면**: 승인 시 **공식 nodejs.org 배포 zip**을 받아 같은 폴더에 준비하는 fallback이
  동작합니다(**채택된 전략 — D90**). 다운로드 파일은 **기록된 기대 SHA-256 + 공식 SHASUMS256.txt 이중 검증**을
  통과해야만 사용되며, 불일치 시 즉시 중단·정리됩니다.
- **거부하거나 실패하면**: 아무것도 설치되지 않고, **기본 텍스트 기반 검토로 계속** 진행됩니다
  (판독 못 한 부분은 확인 불가로 표시되고 고객 확인 질문으로 연결).
- **네트워크는 언제 쓰나**: **준비(다운로드/설치) 단계에서만** 제한적으로 발생하고 기록됩니다.
  **문서 분석 실행 단계는 네트워크 차단(no-egress) 장치 아래에서 로컬로만** 수행됩니다.
  (이 차단 장치는 실행 기록(provenance)으로 확인되는 프로세스 수준 검증이며, 운영체제 방화벽 같은
  보안 보장을 뜻하지 않습니다.)
- **문자 인식(OCR)도 같은 원칙 + 별도 승인**: 스캔/혼합 PDF의 OCR은 HWP-계열 판독 승인과 **별개의
  승인**을 받습니다. 승인 문구에 도구 출처(공식 npm registry)와 **언어 인식 데이터의 별도 출처**(공개
  저장소)가 각각 고지되며, 모든 다운로드 파일은 기록된 SHA-256 검증을 통과해야만 사용됩니다(불일치 시
  즉시 중단·정리). 실행은 문서의 '판독 필요' 페이지만, 페이지 상한·제한시간 안에서 수행되고, 결과
  텍스트는 **정확도가 보증되지 않는 검수용 보조 재료**로만 쓰입니다 — 이 텍스트만으로 근거가 확정되지
  않으며, 최종 판단은 항상 컨설턴트가 합니다.

## 6. 산출물 기대치

- **사전검토 보고서 초안 1개**: KSSB 4대 영역(거버넌스·전략·위험관리·지표 및 목표) 항목별
  판정 라벨 + 원문 인용 근거 + 부족 정보 + **고객 확인 질문·요청자료** + 보완 권고 + 한계·검토 범위 공시.
- 형식: **DOCX 우선**, 제한 시 HTML → Markdown fallback.
- 성격: **consultant-review draft** — 사람이 검수·수정한 뒤 컨설팅 자료로 활용합니다.
- 사용자 요약에는 내부 도구명·로컬 경로·실행 로그가 노출되지 않습니다.

## 7. 2N-5 블랙박스 테스트 시나리오 체크리스트

| # | 시나리오 | 확인 포인트 |
|---|---|---|
| 1 | 텍스트 레이어 PDF (baseline) | 보고서 생성, DOCX primary(+HTML/MD fallback), 가독성 |
| 2 | 텍스트 PDF — **구조 보강 판독 승인**(Kordoc-first 경로) | 승인 대화 이해 가능성, 표·섹션·페이지 위치 신호의 근거 표시 반영, 거부 시 기본 경로 수렴 |
| 3 | 혼합 PDF — OCR **미승인**(baseline) | 한계 실수치 공시, 확인 불가→질문 라우팅, 과장 없음 |
| 4 | 혼합 PDF — **'판독 필요' 페이지 OCR 승인** | 대상 페이지만 문자 인식되는지, OCR 텍스트가 보조 재료(OCR 유래 표기·confirmed 단독 승격 없음)로만 쓰이는지 |
| 5 | 스캔/이미지 전용 PDF — **전 페이지 OCR 승인** | 페이지 상한·제한시간 동작, 산출물 생성, 검수 경계 문구 |
| 6 | OCR **unavailable/거부/설치 실패/무결성 불일치** | 각각 baseline 수렴 + 이해 가능한 안내, 무단 재시도/설치 없음, 불일치 시 정리 후 중단 |
| 7 | OCR **백지 렌더 방어·제한시간 초과·페이지 상한 초과** | 부분 산출물이 남지 않는지, 정중한 거절/실패 안내 |
| 8 | OCR **대상 0페이지**(텍스트만인 PDF에 OCR 시도) | "OCR 불필요" 정중 종료, 산출물 없음 |
| 9 | DOCX 입력 | 문서 수준 ingest·출력 동작, 보조 신호 안전 처리 |
| 10 | HWPX 입력 | baseline/assisted 동작과 한계 표시 |
| 11 | HWP — assisted 미설정 / 사전 준비됨 | 명확한 fallback·승인 흐름·no-egress 실행 기록·산출 연계(기존 경로 회귀 없음) |
| 12 | portable Node 승인 **수락 / 거부·실패**(모의) | 공식 출처·hash 검증·tool-cache 흐름 / A안 수렴·이해 가능한 안내 |
| 13 | 미지원/손상 입력 | fail-fast 또는 확인 불가 라우팅, 허위 근거 없음 |
| 14 | 전달 fallback | DOCX 실패 시 HTML/MD 수렴, user_summary 경로 무노출 유지 |
| 15 | repo/제출물 오염 점검 + **산출물 no-overclaim 점검** | 생성 산출물 미커밋, 보고서에 OCR 지원 완료/준수 확정류 표현 0, provider명·내부 경로 무노출 |
