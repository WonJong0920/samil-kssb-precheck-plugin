# Cycle 2I-0 — Baseline 실행/산출물 문제 분석 (Run A / Run B)

> **성격**: 분석 전용. 코드·Skill·renderer·validator·schema·manifest·marketplace를 **수정하지 않는다.** PASS/FAIL 판정도 하지 않는다.
> 사용자 제공 실행 로그의 로컬 절대경로·계정명은 `[REDACTED]` 처리하고, PDF 원문은 파일명/페이지/섹션 수준으로만 인용한다.

## 1. 분석 개요

- 사용자가 동일 프롬프트("이 보고서 분석해줘")로 Samil KSSB Precheck Plugin을 두 번 실행했다.
  - **Run A — Hana**: `HFG_ESG_KSSB_Report_KOR_2024.pdf`(KSSB 기준에 가까운 지속가능성/KSSB 보고서).
  - **Run B — K-water**: `2024_SMReport_KR.pdf`(GRI·TCFD·SASB 기반 일반 지속가능경영보고서).
- 각 Run은 (1) 플러그인 실행 로그, (2) 최종 산출물을 제공했다.
- 이 문서는 문제를 **① 플러그인 실행 단계 문제**와 **② 산출물 퀄리티 문제**로 나눠 정리한다.
- 사용자 1차 문제의식(출발점): (a) gov/strat 등 내부 코드형 용어, (b) DOCX 미생성, (c) PDF 파악 한계·OCR/표 추출 보완 필요, (d) 실행 문제와 산출물 문제 분리 필요.

## 2. Run A 관찰 결과 (Hana)

- 입력은 실제 KSSB 구조에 가까운 보고서(거버넌스·전략·위험관리·지표/목표 축, Scope 1·2/Scope 3 카테고리, 내부 탄소가격, 감축목표 등 포함).
- 실행 로그: 플러그인에 **문서 변환/OCR이 없어**, 로컬 환경에서 Node/zlib로 PDF 텍스트 스트림을 즉석 추출(FlateDecode + 한글 CID ToUnicode CMap 디코딩)했다. 추출 결과는 임시 파일에 저장(`%TEMP%/…extracted*.txt`).
  - 로그에 **로컬 절대경로**(`[REDACTED]/HFG_ESG_KSSB_Report_KOR_2024.pdf`)와 즉석 스크립트 전문·재시도 과정이 그대로 노출됨.
- 최종 산출물: **채팅형 요약 표**(파일 아님). 항목이 `gov-01/gov-02/strat-01/strat-02/risk-01/metric-01~04/target-01` **내부 코드**로 표기됨.
  - 요약 판정 분포(로그 기준): 근거 확인 다수(9), 일부 근거 확인·보완 필요 1, 확인 불가·상충·범위 외 0.
  - 고객 확인 질문·요청자료·보완 권고·검토 한계가 포함되고, **감사·인증·준수 대체 아님/컨설턴트 검수용/확인 불가를 미공시로 단정하지 않음** 경계 문구 유지.
- **DOCX/HTML 대표 문서 미생성.** 산출물 파일 경로 없음.

## 3. Run B 관찰 결과 (K-water)

- 입력은 KSSB 전용 구조가 아닌 **일반 지속가능경영보고서**(GRI/TCFD/SASB). 파일 크기 156MB.
- 실행 로그: 동일하게 Node/zlib 즉석 추출. **첫 추출 스크립트가 인용부호 파싱에서 실패**해 로직을 단순화하여 재시도. 로컬 절대경로(`[REDACTED]/2024_SMReport_KR.pdf`)·임시 파일 경로 노출.
- 최종 산출물: **채팅형 요약 표**(파일 아님), 동일한 내부 코드(gov/strat/risk/metric/target) 표기.
  - 판정 분포(로그 기준): 일반 보고서 특성상 "일부 근거 확인, 보완 필요"가 다수, Scope 3는 "공개자료로 확인 불가", 내부 탄소가격은 "검토 범위 외 또는 적용대상 아님".
  - 고객 확인 질문 8종·요청자료 포함, 경계 문구 유지.
  - **검토 한계 명시**: "PDF 텍스트 스트림 기반 분석, OCR·표 이미지 복원 미수행 → 표 안 숫자는 원본 대조 또는 요청자료 수령 후 재확인 필요."
- **DOCX 미생성.**

## 4. 플러그인 실행 단계 문제

1. **문서 인테이크(변환/파싱) 단계 부재**: 플러그인에 PDF→텍스트 변환·OCR·표 추출이 설계상 없어(현 SKILL.md 범위 밖), 에이전트가 **즉석 Node/zlib 스크립트로 추출**을 대신함. 재현성·안정성이 낮다(Run B 첫 시도 실패·재시도).
2. **PDF 파싱 한계(한글 CID/CMap)**: 한글 폰트가 ToUnicode CMap을 요구해 일부 문자·수치가 깨져 복원됨. 표/이미지형 수치는 신뢰도 낮음.
3. **표/이미지형 데이터 복원 실패**: 두 Run 모두 "표 안 숫자 재확인 필요"로 귀결 → 정량 지표(Scope 1·2·3, 에너지 사용량 등)의 source-bound 근거가 약화됨.
4. **긴/대용량 문서 처리 한계**: Run B 156MB. 대용량 latin1 로드·정규식 스캔 방식은 메모리·시간 측면에서 취약.
5. **실행 로그의 사용자-facing 노출**: 즉석 추출 스크립트·재시도·내부 처리 과정이 사용자 결과에 섞여 노출됨. Skill 워크플로우의 내부 단계가 그대로 드러남(문서상 "내부 구성요소" 원칙과 어긋남).
6. **민감정보/로컬 경로 노출 위험**: 로그에 `C:/Users/<계정>/…` 형태 **로컬 절대경로·계정명**이 노출됨(제품 경계의 "plugin/cache/sandbox·내부 경로 비노출" 원칙 위배 소지). → 문서화 시 `[REDACTED]` 필요.
7. **DOCX/대표 문서 미생성**: 문서화된 흐름(findings → validator preflight → renderer → 사람 검수)이 **end-to-end로 배선/실행되지 않음.** 산출물이 구조화 findings가 아니라 채팅 요약이며, `src/renderers/kssb_report_renderer.py`(Python stdlib)가 호출되지 않아 `<보고서명>_KSSB_공시근거_사전검토보고서.docx/.html`이 생성되지 않았다.
8. **최종 산출물 경로 부재**: 추출 텍스트는 임시 폴더로 갔고, 사용자에게 반환되는 대표 문서 파일 경로가 없다.

## 5. 산출물 퀄리티 문제

1. **내부 코드명 노출**: `gov-01`·`strat-02`·`metric-04` 등 카탈로그 코드가 사용자에게 그대로 표기됨. 스키마에는 `requirement_title`(한글 항목명)이 있으나 출력은 코드 우선.
2. **사용자 친화 한글 항목명 부족**: 코드 접두어가 붙은 짧은 제목만 제시 → 비전문 사용자가 항목 의미를 파악하기 어려움.
3. **원문 인용 부족**: 출력이 "근거 요지"(요약 서술) 중심이고, `evidence_anchors.quote`에 해당하는 **원문 인용(발췌)**이 사용자 결과에 드러나지 않음.
4. **페이지/섹션/표 위치 단서 부족**: `page_or_section`(예: p.9 / "거버넌스" / 표 식별자)이 사용자-facing 출력에 거의 없음 → 검수자가 원문 대조하기 어려움.
5. **판정 근거 설명 얇음**: 항목당 한 줄 수준 근거로, 컨설턴트가 검수·수정하기엔 설명이 부족.
6. **고객 확인 질문의 요청자료 구체성 편차**: 일부 질문은 요청자료(데이터표·단위·산정범위 등)를 담아 비교적 구체적이나, 요청자료 단위·형식이 항목마다 일관되지 않음.
7. **대표 보고서라기보다 요약문**: 산출물이 표지·고지 → 검토 개요 → 상태 요약 → 영역별 결과·근거 → 고객 질문·요청자료 → 보완 권고 → 한계·사람 검수의 **7섹션 대표 문서 구조가 아니라 채팅 요약 표**에 가깝다.
8. **경계 유지(긍정)**: 두 Run 모두 감사·인증·준수 대체 아님, 컨설턴트 검수용 초안, 확인 불가를 미공시로 단정하지 않음 경계는 **유지됨.** (판정 라벨 체계·source-bound 톤도 대체로 유지)

## 6. 두 Run 비교

| 관점 | Run A (Hana, KSSB형) | Run B (K-water, 일반형) |
|---|---|---|
| 근거 확인 비중 | 높음(근거 확인 다수) | 낮음(보완 필요·확인 불가·범위 외 혼재) |
| 판정 차별화 | 문서 성격 반영해 확인 우세 | 문서 성격 반영해 갭 우세 → **source-bound 동작은 합리적** |
| 추출 안정성 | 즉석 추출 성공 | 첫 시도 실패 후 재시도(대용량·인용부호) |
| 공통 실행 문제 | 로그 노출·로컬 경로 노출·DOCX 미생성·표 수치 신뢰도 | 동일 |
| 공통 산출물 문제 | 내부 코드명·원문 인용/위치 단서 부족·요약형 | 동일 |
| 경계 유지 | 유지 | 유지 |

- **시사점**: 판정 로직·경계는 대체로 정상 동작하지만, **실행 배선(인테이크/렌더링)**과 **표현 품질(코드→라벨, 인용/위치)**이 병목이다. 입력 문서 성격에 따른 판정 차이는 오히려 정상 신호.

## 7. 개선 우선순위 제안

1. **실행 로그와 최종 보고서 분리 + 로컬 경로/민감정보 비노출**: 사용자-facing 결과에서 즉석 추출 스크립트·재시도·`C:/Users/<계정>/…` 경로를 제거하고, 대표 문서만 산출물로 노출.
2. **대표 문서 파일 생성 보장(DOCX, 최소 Markdown/HTML fallback)**: 구조화 findings → renderer 호출을 실제로 배선해 `<보고서명>_KSSB_공시근거_사전검토보고서.docx`(또는 fallback)와 **산출물 경로**를 반환.
3. **내부 코드명 제거 + 한글 항목명 매핑**: 사용자-facing 표기를 `requirement_title`(한글) 중심으로 하고, 코드는 부가 식별자로만(또는 비노출).
4. **원문 인용 + 페이지/섹션/표 위치 단서 강화**: `evidence_anchors.quote`와 `page_or_section`을 사용자 결과에 노출해 검수자 원문 대조를 가능케 함.
5. **PDF 파싱 실패/표 복원 fallback 설계**: 텍스트 추출 실패·표 이미지 구간에 대해 OCR/표 추출 fallback 또는 "확인 불가 → 요청자료" 전환 규칙을 설계(이번 사이클은 설계 제안만).
6. **고객 확인 질문을 요청자료 단위로 구체화**: 질문별 요청자료·단위·산정범위·기준연도를 일관 형식으로.

## 8. 다음 수정 사이클 제안

- **Cycle 2I-1 (실행 배선/출력 분리)**: 로그↔대표 문서 분리, 로컬 경로/민감정보 비노출, findings→renderer 배선으로 대표 문서 파일·경로 보장. *(우선순위 1·2)*
- **Cycle 2I-2 (표현 품질)**: 코드→한글 항목명 매핑, 원문 인용·페이지/섹션 위치 단서 노출, 질문 요청자료 구체화. *(우선순위 3·4·6)*
- **Cycle 2I-3 (문서 인테이크/OCR·표 fallback 설계)**: PDF 파싱 한계·표 복원 실패에 대한 fallback 설계·의존성 판단. *(우선순위 5)*
- 각 사이클은 지시·승인 후 착수. 이번 문서는 **문제 분석·우선순위 제안까지**이며 구현/계획 확정은 하지 않는다.
