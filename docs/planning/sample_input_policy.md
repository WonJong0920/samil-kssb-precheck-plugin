# 샘플 입력자료 처리 정책 (Sample Input Policy)

> **성격**: 계획 문서. 이번 사이클에서 실제 샘플 분석·PDF 반입·submission 생성을 하지 않는다.

## 1. 목적
Samil KSSB Precheck의 사전검토를 검증하기 위한 샘플 입력자료의 **취급 원칙**을 정한다.
목표는 제품 문서를 특정 고객사에 고정하지 않으면서, 향후 재현 가능한 샘플 검증 경로를 확보하는 것이다.

## 2. 샘플 일반화 유형 (제품 문서에 노출 가능한 수준)
샘플은 다음 **2개 유형으로만 일반화**해 다룬다.

1. **유형1 — KSSB 구조 공개 보고서 샘플**: KSSB(제1·2호)/ISSB 4개 축 구조를 갖춘 공개 지속가능성 공시.
   4대 영역(거버넌스·전략·위험관리·지표 및 목표) 매핑 검증에 사용.
2. **유형2 — 일반 지속가능경영보고서 기반 gap-precheck 샘플**: KSSB 전용 구조가 아닌 일반 지속가능경영보고서.
   근거 부족·확인 불가 항목의 고객 확인 질문 전환 검증에 사용.

## 3. 고정 금지 원칙
- README·`product_definition.md` 등 **제품 문서에 회사명·보고서 파일명·공개 출처 URL을 고정하지 않는다.**
- 제품 문서에서는 위 2개 유형으로만 지칭한다.
- 실제 식별정보(회사명·파일명·URL·다운로드 일자)는 **향후 샘플 실행/제출 패키징 단계의 별도 문서**
  (예: `docs/samples/sample_run_log.md` — 후속 사이클에 생성)에만 기록한다.

## 4. 반입·처리 원칙
- **원본 PDF를 repo에 추가하지 않는다.** 저작권·용량·재현성 문제를 피한다.
- 입력은 **텍스트 추출 결과**를 전제로 한다(문서 변환/OCR 실행 코드는 Cycle 1·2A 범위 밖).
- 공개자료는 고객 제공자료의 **대체 입력**으로만 사용한다(해커톤 공개자료 검증 모드).
- **Source-bound**: 샘플 자료에 없는 내용은 근거로 쓰지 않으며, 외부 지식으로 판정을 보강하지 않는다.

## 5. 검증 순서(후속 사이클 실행 대상, 계획)
1. 2개 유형 입력 준비(텍스트 추출, PDF 미커밋).
2. 유형1 실행 → 대표 문서 생성 → 판정 스키마·근거앵커 자기검증.
3. 유형2 실행 → 대표 문서 생성 → 확인 불가→질문 전환 자기검증.
4. 금지표현·제품경계·source-bound 대조.
5. 실제 샘플 식별정보를 별도 실행 로그 문서에 기록.

## 6. 산출물 취급
- 샘플 실행 결과의 대표 문서에 **고정 고객명이 제품 문서로 새어나가지 않도록** 확인.
- 샘플 산출물을 submission에 포함할지는 **패키징 단계에서 결정**(저작권/식별정보 검토 후).
